# Palomar packages for conjecture-proofs

Three results from
[conjecture-proofs](https://github.com/marcosmartinsalvador/conjecture-proofs), each as a
self-contained Lean project in the layout the
[Palomar registry](https://palomar-registry.org/how-to-submit) asks for.

| Folder | Result | Kind |
|---|---|---|
| [`kourovka_20_52_class_deficiency/`](kourovka_20_52_class_deficiency/) | Kourovka problem 20.52: \|G\| − k(G) = 16m is attained for every odd m and every m in which 2 occurs to an odd power | Partial result; the problem is still open |
| [`delta_primitive_two_primes/`](delta_primitive_two_primes/) | 24 and 40 are the only Δ-primitive numbers of the form pˣqʸ | Conjecture proved |
| [`cycle_consistency_probability/`](cycle_consistency_probability/) | The consistency probability of the cycle: the printed formula is false, a corrected one is proved | Disproved as printed; corrected formula proved |

**The proofs were generated by Claude Fable 5.2, an AI model made by Anthropic.** The
author, Marcos Martín Salvador, did not find or write them. Each package's
`formalization.yaml` and `README.md` say so, and say how the proof was checked and
reviewed. No mathematician has reviewed these results.

## How this repository relates to conjecture-proofs

Each package here is a complete Lean development. The full statement and the full
proof are in this repository, each package builds on Mathlib alone, and nothing here
imports or depends on conjecture-proofs. This repository is not a wrapper around it.

conjecture-proofs is where the results were first published, as plain Lean files,
together with their reviews and the checker that accepted them. The Lean text here is
the text of those files at commit
[`a051c72158ef471e5541f0ddad2435755fbb070c`](https://github.com/marcosmartinsalvador/conjecture-proofs/tree/a051c72158ef471e5541f0ddad2435755fbb070c)
(release `v1`), with Lean's `module` header in place of the import line.

## Why a separate repository

The results, their reviews and the checker that accepted the proofs live in
[conjecture-proofs](https://github.com/marcosmartinsalvador/conjecture-proofs). That
checker accepts plain Lean files only. The Palomar registry asks for the opposite:
[every `.lean` file](https://github.com/PalomarRegistry/PalomarPolicy/blob/main/CONTRIBUTING.md#lean-source-requirements)
in the repository a submission points to must use Lean's module system, not only the
files of the package. Both rules cannot hold in one repository, so the packages are
kept here. Every Lean file in this repository starts with the `module` header.

## What is in a package

| File | What it is |
|---|---|
| `Challenge.lean` | The statement: the text of `conjectures/<folder>/Statement.lean` in conjecture-proofs, then `theorem result : Claim := by sorry`. This is the file a reader audits. It imports only Mathlib. |
| `Solution.lean` | The same statement, then the text of `conjectures/<folder>/Proof.lean` in conjecture-proofs, which ends with `theorem result : Claim`. |
| `comparator.json` | Tells `lake comparator` to compare the theorem `result` in the two files, allowing only the axioms `propext`, `Quot.sound` and `Classical.choice`. |
| `formalization.yaml` | Palomar's metadata: author, sources, subject codes, how the proof was produced and reviewed. |
| `README.md` | The account in words: what is proved and what is not, the source's statement, how the Lean statement reads it, the idea of the proof, whether it is new, and how it was produced. |
| `lean-toolchain`, `lakefile.toml`, `lake-manifest.json` | Lean 4.36.0 and Mathlib v4.36.0 (commit `fc4f59e577fe`), the same versions as conjecture-proofs. |

The Lean text was copied, not rewritten, from commit
[`a051c72`](https://github.com/marcosmartinsalvador/conjecture-proofs/tree/a051c72158ef471e5541f0ddad2435755fbb070c)
of conjecture-proofs (its release `v1`); each package's `formalization.yaml` records that
commit in full. Only the import lines differ: `import Mathlib`
became

```lean
module

public import Mathlib

@[expose] public section
```

In `delta_primitive_two_primes` one sentence of a comment, which pointed at files that
are not in the package, was reworded. Nothing that Lean checks was touched.

## Checking

```bash
./verify.sh                 # all three; or: ./verify.sh <folder>
```

`verify.sh` needs Linux, Lean (installed with
[elan](https://github.com/leanprover/elan); each folder's `lean-toolchain` selects Lean
4.36.0), `python3` and `bwrap` (bubblewrap, the sandbox `lake comparator` uses). It
checks that

1. every Lean file in the repository has the `module` header and is within Palomar's
   size limits;
2. the Lean text of each package is the text of `conjectures/<folder>/Statement.lean`
   and `Proof.lean` in conjecture-proofs. This step needs a checkout of that repository,
   next to this one or at the path in the variable `CONJECTURE_PROOFS`; without one it
   is skipped, and the script says so;
3. `lake comparator` accepts each package, with Lean's kernel and the two independent
   kernels shipped with Lean (NanoDa and con-ron), as the registry runs it.

To run the comparison alone, in a package folder: `lake exe cache get && lake
comparator`. It should end with `Your solution is okay!`.

One more check was made when the packages were built, and is not repeated by the
script: the original `conjectures/<folder>/Proof.lean`, compiled as it is in
conjecture-proofs, was exported and given to `lake comparator --solution-from-export`
as the solution to each `Challenge.lean`. All three were accepted. So each
`Challenge.lean` states exactly what the proof accepted by the checker in
conjecture-proofs proves.

## Submitting

One submission per package, on
[the submission form](https://submit.palomar-registry.org/), by the author. For each
one the form needs:

- this repository, and the full commit SHA to be reviewed (`git rev-parse HEAD`);
- the project directory: the package folder, for example
  `kourovka_20_52_class_deficiency`;
- the Comparator configuration: `comparator.json` in that folder, for example
  `kourovka_20_52_class_deficiency/comparator.json`.
