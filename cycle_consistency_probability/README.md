# Random equations on a cycle: the printed formula is wrong, the corrected one is proved

**The conjecture as printed is disproved; a corrected formula is proved.**

This folder is a self-contained Lean project in the layout the
[Palomar registry](https://palomar-registry.org/) asks for. The result's own page, with
the original files and the checker's output, is
[`conjectures/cycle_consistency_probability/`](https://github.com/marcosmartinsalvador/conjecture-proofs/tree/main/conjectures/cycle_consistency_probability).

## What is proved

Put one random equation in two variables over the field with two elements on each edge
of a cycle with n edges. The source conjectures an exact formula for the probability
q(C_n) that the system has a solution.

**Proved here**, for every n ≥ 3:

- the exact value is q(C_n) = s^n + t^n − 1/4^n − 1/(2·8^n), with s, t = (17 ± √97)/32;
- the formula as printed, whose last term is 1/8^(n−1), is not equal to q(C_n).

The last term in the paper is 16 times too large. For the triangle, q(C_3) = 2397/4096
by direct count over all 16³ systems, while the printed formula gives 2337/4096.

This should not be described as "the paper's conjecture proved". The corrected formula
is a statement made here, and it is not known which formula the authors meant. Most
likely the last term is a misprint; that is a guess.

**Not treated:** graphs other than cycles.

## The statement as printed

P. Horak, I. Semaev, "Inconsistency Probability of Sparse Equations over F2",
arXiv:2603.24890v1 (26 March 2026), the conjecture of the last subsection:

> **Conjecture.** The consistency probability of the cycle $C_{n}$ is given by
> $$q(C_{n})=s^{n}+t^{n}-\frac{1}{4^{n}}-\frac{1}{8^{n-1}},$$
> where $s=\frac{17+\sqrt{97}}{32},t=\frac{17-\sqrt{97}}{32}.$

## How the Lean statement reads it

In [`Challenge.lean`](Challenge.lean):

- The vertices of C_n are `ZMod n`; edge `i` joins `i` and `i + 1`. For n ≥ 3 this is
  the simple cycle with n vertices and n edges.
- The equation on edge `i` is `f i (x i) (x (i + 1)) = 0`, with
  `f i : ZMod 2 → ZMod 2 → ZMod 2` arbitrary. Every function of two variables over the
  field with two elements is a polynomial function, and there are 16 of them, as in the
  paper. Which end of an edge is the first argument does not matter, because all 16
  functions are allowed.
- `Consistent n f` says that one assignment satisfies all n equations. `qCycle n` is
  the number of consistent systems divided by 16^n.
- `Claim` says both things above for every n ≥ 3. The second formula in it is the
  paper's, term for term; `8 ^ (n - 1)` uses natural-number subtraction, which is exact
  because n ≥ 3. The compared theorem is `result : Claim`.

## Idea of the proof

Record each equation as a 2×2 Boolean matrix (entry (a, b) is 1 when f(a, b) = 0). The
system on the cycle is consistent exactly when the Boolean product of the n matrices
has a nonzero diagonal entry. The number of sequences of n ≥ 1 Boolean matrices with a
given product has a closed form in terms of 16^n, 4^n, 2^n and the sequence
u_0 = 0, u_1 = 1, u_(n+2) = 17u_(n+1) − 48u_n (the table `G` in
[`Solution.lean`](Solution.lean)); it is proved by induction, the step being one finite
identity. Adding up gives 2u_(n+1) − 17u_n − 4^n − 2^(n−1) consistent systems, and
2u_(n+1) − 17u_n = ((17 + √97)/2)^n + ((17 − √97)/2)^n.

## Is it new?

**Fairly sure.** Nothing was found on this conjecture anywhere: no proof, no
correction, no earlier formalization. The paper has only one version on arXiv.

Not searched: citation indexes and journal databases (MathSciNet, zbMATH, Google
Scholar). No search can show that nobody did this before.

## How it was produced

**The proof was generated by Claude Fable 5.2, an AI model made by Anthropic, working
through Claude Code. The author, Marcos Martín Salvador, did not find or write it.**
One AI session found that the printed formula fails, found the corrected formula, and
wrote the Lean statement and proof. A separate AI session, which did not write the
proof, read the paper's definitions, counted the consistent systems with its own
program for n = 3 to 7, and searched for earlier work. A fixed checker script, which
the sessions could not change, accepted the proof. The author set up the project and
its rules, read the reports and decided what to publish. The README of
[conjecture-proofs](https://github.com/marcosmartinsalvador/conjecture-proofs) names this
as one of the proofs the author has studied closely enough to explain. No
mathematician has reviewed this result.

## Files, and how to check them

- [`Challenge.lean`](Challenge.lean): the statement, with the theorem left open. Its
  definitions are the text of
  [`Statement.lean`](https://github.com/marcosmartinsalvador/conjecture-proofs/blob/main/conjectures/cycle_consistency_probability/Statement.lean),
  unchanged.
- [`Solution.lean`](Solution.lean): the same statement, then the proof, which is the
  text of [`Proof.lean`](https://github.com/marcosmartinsalvador/conjecture-proofs/blob/main/conjectures/cycle_consistency_probability/Proof.lean),
  unchanged. Only the import lines were replaced by a `module` header.
- [`comparator.json`](comparator.json): tells `lake comparator` to compare the theorem
  `result` in the two files.
- [`formalization.yaml`](formalization.yaml): the registry's metadata.
- `lean-toolchain`, `lakefile.toml`, `lake-manifest.json`: Lean 4.36.0 and Mathlib
  v4.36.0, pinned.

To check, on Linux with Lean and `bwrap` installed: `../verify.sh
cycle_consistency_probability`, or `lake exe cache get && lake comparator` in this
folder. It should end with `Your solution is okay!`.
